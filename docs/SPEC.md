# tokenbox — 仕様

status: v0.2（2026-11-21）。`register` / `get` は実装済み（v0.1.0）。確定した点と未確定の点を分けて書く。

## 1. 目的と範囲

- tokenbox は、git repo（store）に秘密を暗号化して入れ、取り出すためのコマンド。**仕組みだけ** を提供する。
- tokenbox が知るのは、引数で渡された **git URL** と **key 名** の 2 つだけ。
- tokenbox が知らないもの: 誰が起動するか、秘密が何に使われるか、取り出した値がどこに置かれるか、store の場所の既定値、key 名の一覧。これらはすべて利用側の管理であり、この仕様の範囲外。
- ホストに何も残さない。設定ファイル、鍵ファイル、git URL、store の写しのいずれも保存しない。

## 2. モデル

```
            store: 任意の git repo（public。git URL は引数で渡す）
            ┌─────────────────────────────────────────────────┐
            │ <key 名から導出した名前>   (key 名から導出した鍵で   │
            │                            暗号化した値)          │
            └─────────────────────────────────────────────────┘
                 ▲ register（push。ホストの git 設定の認証）
                 │
                 ▼ get（取得。無認証）
   tokenbox <git-url> register <key-name>
   tokenbox <git-url> get <key-name>
```

- 読める条件は **git URL と key 名の両方を知っていること**。それ以外の鍵（ホスト鍵、共通鍵、recipients）は持たない。
- store には元の key 名を置かない。ファイル名は key 名から導出した値で、値は key 名から導出した鍵で暗号化する。
- 鍵の材料は key 名のみ。git URL は混ぜない（同じ repo でも URL の表記が変わると復号できなくなるため）。

## 3. CLI

バイナリ名 `tokenbox`。起動形は `tokenbox <git-url> <command> ...`。git URL は毎回必須の位置引数で、既定値も保存もない。

| コマンド | 動作 |
|---|---|
| `tokenbox <git-url> register <key-name>` | 値を受け取り、暗号化して store に入れる（commit、push）。同じ key 名で再度実行すると値を置き換える |
| `tokenbox <git-url> get <key-name>` | store から取得し、復号した値と改行 1 つを stdout に出す。TTY なら拒否（`--force-tty` で許可） |

`register` の値の入力経路:

| 指定 | 入力元 |
|---|---|
| （指定なし） | 隠し入力（端末で打つ、または貼る。画面に出さない） |
| `--clipboard` | クリップボードの値。画面の無い環境では使えない。OS のコマンドで読む（macOS: `pbpaste`、Linux: `wl-paste` → `xclip` → `xsel` の順に試す、Windows: PowerShell の `Get-Clipboard`） |
| `--stdin` | 標準入力。スクリプトやエージェントのセッションが値を流し込む |

- 値をコマンドライン引数で受け取る形は持たない（引数はプロセス一覧に出る）。
- 入力の末尾の改行は 1 つだけ取り除く（`echo value | tokenbox ... --stdin` で改行が値に入らない）。空の値は使い方の誤り。
- 取り出した値をファイルに置く、権限を設定する、他のツールの設定を書き換える、といった配置は行わない。`get` の出力を受けた利用側が行う。
- 共通オプション: `--json`（`get` は `{"value":"..."}`、`register` は `{"status":"registered","commit":"..."}`）、`-q`。

終了コード: 0 成功 / 1 使い方の誤り / 2 復号不可（key 名が違う、または未登録） / 3 store に到達できない・取得や push の失敗 / 4 store が認証を要求した（public 必須。§5）。

## 4. store の形式

- 1 つの秘密が 1 つのファイル。置き場は `v1/<ファイル名>`。`v1` は store の形式の版。
- 導出: key 名を Argon2id（メモリ 64 MiB、3 回、並列 1、固定の salt `tokenbox/v1/key-name`）に通して 64 バイトを得る。前半 32 バイトの 16 進表記がファイル名、後半 32 バイトが暗号鍵。
- ファイル名から key 名を総当たりするには、候補 1 つごとに Argon2id を 1 回計算する必要がある。前半から後半（暗号鍵）は求められない。
- ファイルの中身: `TBX1`（4 バイト）+ nonce（24 バイト、毎回ランダム）+ XChaCha20-Poly1305 の暗号文。
- store には、key 名、秘密の用途、配置先など、値以外の情報を置かない。commit のメッセージは固定文（`tokenbox: register`）。

## 5. store の条件と認証

- store は **public 必須**。private の store での運用は仕様の範囲外。
- 取得（`get`、および `register` の事前取得）は常に無認証で行う。認証情報を送らない。
- サーバーが認証を要求したら、「store は public 必須」としてエラー終了する（終了コード 4）。git プロトコルでは private と「URL の誤り・repo が無い」を区別できないことがあるため、エラー文には両方の可能性を書く。
- 書き込み（`register` の push）のときだけ認証を使う。認証はホストの git 設定から読む。HTTP(S) は credential helper、SSH は ssh-agent。tokenbox は token やパスワードを受け取らず、保存もしない。
- credential helper の実行には、その helper を提供するプログラム（多くは git に付属）がホストに要る。読み取りには要らない。
- 取得が無認証のため、store の git URL は HTTP(S) かローカルパスを使う（SSH の URL は常に認証を要求する）。

## 6. git の扱い

- `git` コマンドを使わない。git プロトコルの実装として `git2` crate（libgit2 を同梱）をリンクする。
- git プロトコルはファイル単位の取得ができないため、受け皿として一時的な bare repo を作る。最新の 1 commit だけを取得する（depth 1）。
- 受け皿は実行ごとに一時ディレクトリに作り、成功・失敗にかかわらず終了時に消す。
- depth 1 の取得ができない経路（ローカルパスなど）では、全体を取得する。
- store に commit が無いときは、`register` が最初の commit を `main` に作る。
- push が「先に他の push があった」で拒否されたら、取得からやり直す（3 回まで）。

## 7. セキュリティ要件と性質

- 値を含むログ・エラー・デバッグ出力を出さない（`Display` 実装で伏せる型 `Secret<String>` を使う）。
- 一時ディレクトリは所有者のみ読み書きできる権限で作る。失敗時も削除する。
- `get` は TTY では拒否（うっかり人の画面に出さない）。
- 強さは key 名の推測しにくさで決まる。暗号文は誰でも取得できるため、短い・ありふれた key 名は総当たりで当てられる。key 名には長いランダムな部分を付ける（例: `service-token-xxxx-xxxx-xxxx`）。ランダムな部分は利用側が決める。
- 取り消しの仕組みは無い。git URL と key 名を知った者は、その後も読める。値を置き換えても古い暗号文は git の履歴に残る。知られたくない相手に知られた場合は、秘密そのものを発行し直し、新しい key 名で `register` する。

## 9. この仕様に含めないもの

- 秘密の一覧、key 名と用途の対応、store の git URL の記録。
- 取り出した値の配置（ファイル、権限、他ツールの設定）。
- ホストの登録・削除、期限の管理。
- 特定のネットワークでの運用手順、既存の仕組みからの移行手順。
